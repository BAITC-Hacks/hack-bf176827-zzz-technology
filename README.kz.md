# Ақша графы — Граф денег

[Русский](README.md) · **Қазақша (KZ)** · [English (EN)](README.en.md)

**Қаржылық мониторингке арналған банк аударымдары желісін түсіндірмелі талдау.**
**HackAlem AI** хакатонына арналған **Zzz Technology** командасының жобасы.

«Ақша графы» талдаушыға транзакциялар желісіндегі қай түйіндерді алдымен тексеру
керектігін анықтауға көмектеседі: қаражатты кім жинайды, әрі қарай өткізеді,
алушыларға таратады немесе топтарды байланыстырады. Әр клиент үшін рөл,
тексеру басымдығы және бастапқы аударымдармен салыстыруға болатын негіздеме беріледі.

**Жүйенің қорытындылары — тексеруге арналған гипотезалар, құқық бұзушылықтың дәлелі емес.**

## Іске асырылған мүмкіндіктер

- Үш Parquet файлын жүктеу және біріктірілген қырларды бастапқы транзакциялармен
  клиенттер жұбы, аударым саны және сомасы бойынша салыстырып тексеру.
- Кіріс/шығыс байланыстары мен сомаларын, PageRank, HITS, аралық орталықтылықты
  (betweenness), транзит үлесін, графты аралаудың бастапқы түйіндерімен (`seed`)
  байланысты және белсенділіктің уақыттық белгілерін есептеу.
- Алты рөлдің бірін, `role_score` бағасын, кластерді, `priority_score`
  басымдығын және `evidence` мәтіндік негіздемесін тағайындау.
- Louvain кластерлеуі, бес түйінге дейінгі тұйық циклдер мен қайталанатын
  A → B → C маршруттарын іздеу, басым түйіндерді алып тастаудың желіге әсерін есептеу.
- React интерфейсі: бағытталған граф, толық gid немесе префикс арқылы іздеу,
  рөл мен кластер сүзгілері, топ-30, клиент карточкасы, көршілерге өту,
  бір/екі қадамдық маңай және карточканы көшіру.
- Үш CSV файлы мен `graph.json` экспорттау, нәтижелерді тексеретін жеке валидатор,
  HTTP API және Swagger.
- Қосымша AI мүмкіндіктері: түйіндер туралы анықтамалар, кластер гипотезаларын
  тұжырымдау және графты оқу құралдары арқылы сұрақтарға жауап беру.

| Рөл | Мағынасы |
|---|---|
| `consolidator` | Бірнеше төлеушіден қаражат жинап, едәуір бөлігін ұстап қалады |
| `transit` | Алған қаражатына шамалас соманы әрі қарай өткізеді |
| `distributor` | Қаражатты көптеген алушыға таратады |
| `terminal` | Қарастырылып отырған деректер аясындағы соңғы алушы |
| `coordinator` | Топтарды байланыстырады және аралық орталықтылығы жоғары |
| `peripheral` | Басқа рөлдерді тағайындауға жеткілікті белгілер жоқ |

## Шешім қалай жұмыс істейді

1. Пайплайн `data/nodes.parquet`, `edges.parquet` және `transactions.parquet` файлдарын оқиды.
2. Графты құрып, метрикаларды, кластерлерді және аударым үлгілерін есептейді.
3. Ережелер рөлдерді тағайындайды; метрикалардың перцентильдік рангтеріне негізделген
   формула тексеру басымдығын анықтайды. Нәтижелер `out/` каталогына сақталады.
4. Веб-сервер ортақ талдау нәтижесін жедел жадта есептеп, API арқылы ұсынады.
5. Талдаушы топ-30 тізімін ашады немесе клиенттің gid мәнін енгізеді, карточканы,
   байланыс сомалары мен бағыттарын қарайды, контрагенттерге өтіп, маңайды кеңейтеді.
6. Қажет болса, мәтіндік анықтама алады немесе ассистентке сұрақ қояды.

Рөлдер мен басымдықтарды жергілікті алгоритм есептейді. LLM дайын фактілерді
алады және рөлдерді, кластерлерді немесе басымдықтарды **тағайындамайды**.

Кластерлеу аударым сомаларымен өлшенген бағытталмаған проекцияда, кездейсоқ сандар
генераторының бекітілген бастапқы мәнімен орындалады. Басымдық кіріс көлемін,
төлеушілер санын, тізбектің алдыңғы бөлігіндегі seed түйіндерін, PageRank,
аралық орталықтылықты және рөлді ескереді. Seed түйіндеріне және аралау шекарасындағы
түйіндерге төмендету көбейткіштері қолданылады. Формулалар, шектер мен түсіндірмелер
[әдістемеде](docs/methodology.md) берілген (орыс тілінде).

## Технологиялар

| Құрамдас бөлік | Іске асырылуы |
|---|---|
| Бэкенд және CLI | Go; модульдегі Go нұсқасы — `1.25.7` |
| HTTP, тәуелділіктер және баптаулар | Fiber v2, Uber FX, Viper, godotenv, zap, validator |
| Деректер және граф алгоритмдері | `parquet-go`, Gonum, метрикалар мен ережелердің жеке есептеулері |
| Фронтенд | JavaScript, React 19, Vite 7, Cytoscape.js 3.30.4, CSS |
| API құжаттамасы | swag / fiber-swagger |
| AI | OpenAI Responses API; `config/base.yaml` ішіндегі әдепкі модель — `gpt-5.1` |
| Құрастыру және іске қосу | Make, Docker, Docker Compose; React құрастыру кезеңінде Node.js |
| Сақтау | Parquet, CSV, JSON; талдау нәтижесі жедел жадта, дерекқор жоқ |

Модель мен API мекенжайы `LLM_MODEL` және `LLM_BASE_URL` арқылы бапталады.
Cytoscape пен React жергілікті жинаққа кіреді: браузерге сыртқы CDN қажет емес.

```mermaid
flowchart LR
    D[Parquet файлдары] --> L[Жүктеу және тексеру]
    L --> M[Граф және метрикалар]
    M --> C[Кластерлер және үлгілер]
    C --> R[Рөлдер және басымдықтар]
    R --> E[CSV және JSON экспорты]
    R --> A[Жадтағы талдау нәтижесі]
    A --> API[Fiber API]
    API --> UI[React және Cytoscape]

    A --> S[Ассистент сервисі]
    S <--> K[JSON кэші]
```

Docker ішінде **бір `app` сервисі** қолданылады. React образдың бөлек кезеңінде
құрастырылады, содан кейін Go дайын статикалық файлдар мен API-ді 8080 портында
ұсынады. Бұл тәсілге бөлек Nginx, Node сервері немесе Postgres қажет емес.

| Каталог | Мақсаты |
|---|---|
| `cmd/pipeline`, `cmd/check`, `cmd/web`, `cmd/ask` | Талдау, экспортты тексеру, сервер және ассистент CLI-і |
| `internal/app`, `internal/config` | Тәуелділіктерді байланыстыру және конфигурация |
| `internal/repo/dataset` | Parquet оқу және тексеру |
| `internal/data/models`, `internal/data/graph` | Пәндік модельдер, граф және индекстер |
| `internal/services/analysis` | Метрикалар, рөлдер, кластерлер, басымдықтар және үлгілер |
| `internal/services/pipeline`, `export`, `graph` | Орындалуды үйлестіру, экспорт және нәтижелерге қол жеткізу |
| `internal/services/assistant`, `hypotheses`, `pkg/llm` | AI сценарийлері, API клиенті және кэш |
| `internal/data/dto`, `internal/transport/http` | JSON келісімдері және HTTP өңдегіштері |

| `web` | Кіріктірілген резервтік қарау интерфейсі және тестілік граф |
| `data`, `out`, `docs`, `tests` | Кіріс деректері, нәтижелер, құжаттама және тестілер |

## Орнату және іске қосу

### 1. Жобаны алу

```bash
git clone https://github.com/BAITC-Hacks/hack-bf176827-zzz-technology.git
cd hack-bf176827-zzz-technology
```

Командаларды репозиторийдің түбірінен орындаңыз. Тәуелділіктерді алғаш жүктеу
және Docker образын құрастыру үшін интернет керек. Құрастырылғаннан кейін
негізгі талдау мен графты қарау OpenAI кілтінсіз жергілікті түрде жұмыс істейді.

### 2. Іске қосу тәсілін таңдау

**Docker — Go мен Node.js-ті жергілікті орнату қажет емес.** Docker Engine/Desktop
және Docker Compose керек. WSL ішінде Docker Desktop қолдансаңыз, WSL integration қосулы болуы тиіс.

```bash
docker compose up --build
# Make бар болса, балама команда:
make docker
```

Образда деректер, React жинағы және үш Go орындалатын файлы бар. Іске қосылғанда
пайплайн орындалады, CSV тексеріледі және веб-сервер ашылады. Хосттағы `out/`
каталогы контейнерге жалғанады: нәтижелер мен LLM кэші сол жерде сақталады.

**React-пен жергілікті іске қосу.** Go **1.25.7+**, Node.js **22.12+**
(немесе 24), npm және Make қажет.

```bash
make demo-full
```

Команда фронтенд тәуелділіктерін орнатып, React-ті құрастырады және
`pipeline → check → web` тізбегін орындайды. `-j` параметрін қоспаңыз:
сервер интерфейс құрастырылғаннан кейін іске қосылуы керек.

React бұрын құрастырылған болса, қайта іске қосу:

```bash
make demo
```

`make demo` React-ті құрастырмайды. `frontend/dist/index.html` болмаса,
сервер кіріктірілген `web/` қарау интерфейсін қолданады.

### 3. Қолданбаны ашу

- Интерфейс: **http://localhost:8080**.
- Swagger: **http://localhost:8080/swagger/index.html**.
- Сервердің қолжетімділігін тексеру: **http://localhost:8080/v1/health**.
- Талдау нәтижелері: **`out/`** каталогы.

Жергілікті процесс ағымдағы терминалда жұмыс істейді; тоқтату үшін `Ctrl+C` басыңыз.
Docker үшін: `docker compose down` немесе `make docker-down`.

### Фронтендті әзірлеу

Бірінші терминалда API-ді іске қосыңыз:

```bash
make web
```

Екінші терминалда:

```bash
cd frontend
npm ci
npm run dev
```

Vite http://localhost:5173 мекенжайында жұмыс істеп, API сұрауларын 8080 портына
бағыттайды. Бэкендтің басқа мекенжайын `API_PROXY_TARGET` арқылы беруге болады.

### Баптаулар және WSL

Құпия емес баптаулар `config/base.yaml` және `config/<APP_ENVIRONMENT>.yaml`
файлдарынан оқылады. Негізгі орта айнымалылары:

| Айнымалы | Әдепкі мәні / мақсаты |
|---|---|
| `APP_PORT` | `8080`, жергілікті Go серверінің порты |
| `APP_DATA_DIR` | `data`, кіріс файлдарының каталогы |
| `APP_OUT_DIR` | `out`, нәтижелер мен кэш каталогы |
| `APP_ENVIRONMENT` | `local`; Docker ішінде `prod` |
| `OPENAI_API_KEY` | Жаңа LLM сұрауларына арналған қосымша кілт |
| `LLM_MODEL` | `gpt-5.1` |
| `LLM_BASE_URL` | `https://api.openai.com/v1` |

`.env` міндетті емес; `make env` оны файл әлі жоқ болса ғана `.env.example`
үлгісінен жасайды. Кілтті бастапқы кодқа жазбаңыз. Compose ішінде `OPENAI_API_KEY`
айқын беріледі; контейнердің басқа баптауларын өзгерту үшін `docker-compose.yaml`
ішіндегі `environment`, ал порт өзгерсе, `ports` бөлімін де өзгерту керек.

WSL ішінде `\\wsl.localhost\...` жолындағы Windows npm орнына Node.js пен Go-дың
Linux нұсқаларын қолданыңыз. Егер `GOROOT` ішінде Windows жолы сақталып қалса:

```bash
unset GOROOT
node -p 'process.platform'  # linux шығуы керек
command -v node
command -v npm
make demo-full
```

8080 порты бос болмаса, алдыңғы процесті тоқтатыңыз немесе жергілікті түрде
`APP_PORT=8081 make demo-full` орындап, http://localhost:8081 мекенжайын ашыңыз.

## Шешімді тексеру: қазылар алқасына арналған сценарий

1. `make demo-full` немесе `docker compose up --build` орындаңыз.
   CSV тексеруі **2248 бірегей түйін** туралы хабарламамен аяқталуы керек.
2. Интерфейсті ашыңыз. Бастапқы көрініс — көршілерімен бірге топ-30;
   түстер рөлдерді, ромбтар seed түйіндерін, жебелер аударым бағытын көрсетеді.
3. **`100000003115284100`** енгізіп, Enter немесе «Найти» (Іздеу) түймесін басыңыз.
   Жиынтықтағы деректерде бұл — `consolidator`: **8 кіріс** және **2 шығыс**
   контрагенті бар, **2 160 500 KZT** алған, **517 000 KZT** жіберген.
   Карточка ашылып, оның байланыстары ерекшеленуі керек.
4. Карточкадағы көршіні, содан кейін «Ego 2 шага» (екі қадамдық маңай) түймесін басыңыз.
   Басқа түйінге өтуді және маңайдың кеңеюін тексеріңіз.
5. Рөл және кластер сүзгілерін тексеріңіз. Екеуін де бастапқы күйге қайтарып,
   «Вся сеть» (Бүкіл желі) түймесін басыңыз: осы деректер жиынтығында
   **2248 түйін және 3119 қыр** болуы керек.
6. `out/nodes_roles.csv` файлын ашып, gid, рөл және негіздемені интерфейспен
   салыстырыңыз. gid мәнін жылжымалы нүктелі санға түрлендірмеңіз.

Қосымша клиент мысалдары мен көрсетуге арналған сұрақтар:
[docs/demo.md](docs/demo.md) (орыс тілінде).

### API арқылы тексеру

Сервер іске қосылғаннан кейін екінші терминалда орындаңыз:

```bash
curl -f http://localhost:8080/v1/health
curl -f 'http://localhost:8080/v1/top?n=3'
curl -f http://localhost:8080/v1/nodes/100000003115284100
curl -f 'http://localhost:8080/v1/nodes/100000003115284100/ego?depth=2'
curl -f http://localhost:8080/v1/assistant/status
```

Карточканың толық метрикалары `node.features` ішінде. JSON ішіндегі барлық gid
мәндері жол түрінде беріледі, себебі олар JavaScript дәл көрсете алатын бүтін
сандар ауқымынан асады. Қате параметр HTTP 400, белгісіз түйін 404 қайтарады.

### Автоматты тексерулер

```bash
make pipeline
make check
make test
go build ./...
cd frontend
npm ci
npm test
npm run build
```

`make check` түйіндер саны мен бірегейлігін, рұқсат етілген рөлдерді,
бағалардың [0,1] аралығында болуын, 200 таңбадан аспайтын бос емес негіздемені,
кластерлердің бар болуын және кемінде 20 жазбадан тұратын реттелген топ-тізімді
тексереді. Қате болса, нөлден өзге шығу кодын қайтарады. Go тестілері талдаудың
детерминизмін, рөл шектеулерін, граф сүзгілерін және HTTP келісімдерін тексереді;
фронтенд тестілері графпен жұмыс істеу операцияларын тексереді.

## Деректер, нәтижелер және интеграциялар

Репозиторийге **2026 жылғы 1–31 шілде** аралығындағы аударымдар енгізілген:
**2248 клиент, 3119 біріктірілген бағытталған қыр, 4840 транзакция және 81 seed түйіні**.
Ақша сомалары KZT түрінде берілген.

| Дереккөз | Parquet өрістері |
|---|---|
| `data/nodes.parquet` | `gid`, `depth`, `is_seed` |
| `data/edges.parquet` | `src`, `dst`, `sum_kzt`, `n_tx`, `depth` |
| `data/transactions.parquet` | `src`, `dst`, `date`, `sum_kzt` |

Деректер файлдар түрінде берілген: банк жүйесіне немесе нақты уақыттағы
транзакциялар ағынына қосылу жоқ. Бастапқы іріктеу шарттары — seed түйіндерінен
шығыс аударымдары бойынша төрт қадамдық аралау және 5000 KZT шегі — әдістемеде сипатталған.

| Нәтиже | Негізгі өрістер |
|---|---|
| `out/nodes_roles.csv` | `gid,role,role_score,cluster_id,priority_score,evidence` және метрикалар |
| `out/clusters.csv` | `cluster_id,n_nodes,n_seed,sum_kzt_internal,top_gids,hypothesis` және жиынтық көрсеткіштер |
| `out/top_nodes.csv` | `rank,gid,role,priority_score,why` |
| `out/graph.json` | `nodes,edges,clusters,top,robustness` |
| `out/llm_cache.json` | Мәтіндік жауаптар мен гипотезалар кэші |

Ағымдағы деректерді есептеу нәтижесі — **88 кластер** және **30 түйіннен** тұратын
топ-тізім. Рөлдер бойынша: 31 consolidator, 43 coordinator, 16 distributor,
105 transit, 153 terminal, 1900 peripheral. Бұл сандар берілген жиынтықты
сипаттайды, модель дәлдігінің бағасы емес.

### HTTP API

| Әдіс және жол | Мақсаты |
|---|---|
| `GET /v1/health` | Сервердің қолжетімділігі |
| `GET /v1/graph?role=&cluster=&component=&top=30` | Графты сүзу; бір қадамдық көршілерімен бірге топ-N |
| `GET /v1/nodes/{gid}` | Метрикалар және кіріс/шығыс контрагенттері бар карточка |
| `GET /v1/nodes/{gid}/ego?depth=1` | Екі бағыттағы маңай, тереңдігі 1–2 |
| `GET /v1/top?n=30` | Есептелген топ-тізімдегі басым түйіндер |
| `GET /v1/clusters` | Кластерлер және гипотезалар |
| `GET /v1/search?q=1000&limit=10` | gid префиксі бойынша іздеу |
| `GET /v1/assistant/status` | LLM баптауының күйі және модель |
| `GET /v1/nodes/{gid}/card` | Мәтіндік анықтама |
| `POST /v1/assistant` | Сұрақ: `{"question":"..."}`; мәтін мен gid бар жауап |
| `GET /graph.json` | Интерфейстің резервтік дереккөзіне арналған соңғы экспорт файлы |

`/v1/graph` үшін `top` параметрін бермеу немесе `top=0` бүкіл желіні білдіреді.
`/v1/top` іске қосу кезінде есептелген топ-тізімнің көлемімен шектеледі.

### Қосымша AI мүмкіндіктері

Жалғыз сыртқы AI интеграциясы — **OpenAI Responses API**. Жаңа жауаптар алу үшін
орта айнымалыларында немесе `.env` ішінде `OPENAI_API_KEY` мәнін беріп, серверді
қайта іске қосыңыз. Мұндай сұрауларда граф фактілері мен түйін идентификаторлары
сыртқы API-ге жіберіледі.

Кілтсіз режимде:

- Талдау, рөлдер, басымдықтар және интерфейс жергілікті түрде жұмыс істейді.
- Кластер гипотезалары кэштен алынады немесе үлгі бойынша құрастырылады.
- Түйін анықтамасы кэштен немесе үлгі бойынша қайтарылады.
- Сұрақ кэште болса, ассистент жауабы қолжетімді. Жаңа сұраққа API 503 қайтарады;
  503 жауабынан кейін интерфейс қолжетімсіз AI элементтерін жасырады.

Әдеттегі пайплайн модельден жаңа гипотезаларды сұрамайды. Оны арнайы қосу үшін:

```bash
go run ./cmd/pipeline --data data --out out --llm
# CLI арқылы түйін анықтамасы; кілтсіз де жұмыс істейді:
go run ./cmd/ask --card 100000003115284100
# Жауап кэште болмаса, жаңа сұраққа кілт қажет:
go run ./cmd/ask --q 'Қай түйіндердің басымдығы ең жоғары және неліктен?'
```

## Ағымдағы нұсқаның шектеулері

- Тек берілген іріктеме көрінеді: клиенттің толық тарихы, шектен төмен аударымдар
  және аралау шекарасынан тыс ағындар жоқ. Төртінші қадамдағы түйіннің шығыс
  аударымдары болмауы ақшаның сол түйінде қалғанын дәлелдемейді.
- Рөлдер эвристикаларға негізделген. Репозиторийде дәлдікті өлшеуге арналған
  эталондық белгілер жоқ; `role_score` құқық бұзушылықтың расталған ықтималдығы емес.
- Талдау іске қосылғанда жедел жадта орындалады. Өндірістік ауқымға масштабтау,
  ағындық жаңарту және интерфейс арқылы жаңа файлдарды жүктеу іске асырылмаған.
  `cmd/check` валидаторы хакатон жиынтығындағы 2248 түйінге бейімделген.
- Кластерлеу бағытталмаған проекцияны қолданады. Аударым графында бағыт сақталады,
  бірақ топтастырудың осы кезеңінде қолданылмайды.
- Бүкіл желіні экранға орналастыру біраз уақыт алуы мүмкін. Әдепкі көрініс —
  көршілері бар шағын топ-30 ішкі графы; уақыт компьютер мен браузерге байланысты.
- React карточкасы негізгі метрикаларды көрсетеді. Толық жиынтық API ішіндегі
  `node.features` өрісінде қолжетімді; барлық ішкі метрикалар интерфейске шығарылмаған.
- Пайдаланушыларды авторизациялау және қолжетімділік құқықтарын бөлу іске асырылмаған.
  Ағымдағы конфигурация жергілікті демонстрацияға арналған.
- Жаңа AI жауаптарына сыртқы API мен кілт қажет. Мәтінде қателер болуы мүмкін,
  сондықтан оны бастапқы фактілермен тексеру керек. Жобаға арнайы үйретілген
  жеке ML моделі кірмейді.
